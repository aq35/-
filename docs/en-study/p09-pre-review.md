| EN | Changes |
|:---|:---|
| 読み | チェインジズ |

| EN | Development policy |
|:---|:---|
| 読み | ディヴェロップメン(ト) ポリスィ |
| JP | 開発方針（の文書） |

## [Request]（お願い）

読み: リクエスト

| EN | For each policy item, judge whether this change "follows it / breaks it / is not related". |
|:---|:---|
| 読み | フォー イーチ ポリスィ アイテム、ジャッジ ウェザー ディス チェインジ "フォロウズ イッ(ト) / ブレイクス イッ(ト) / イズ ノッ(ト) リレイティッ(ド)" |
| JP | 方針の項目ごとに、この変更が「守っている / 破っている / 関係ない」のどれかを判定してください。 |

| EN | For "breaks it", give the path and line of the code, the policy item, and a suggested fix. |
|:---|:---|
| 読み | フォー "ブレイクス イッ(ト)"、ギヴ ザ パス アン(ド) ライン オヴ ザ コウド、ザ ポリスィ アイテム、アン(ド) ア サジェスティッ(ド) フィックス |
| JP | 「破っている」には、コードのパスと行、方針の項目、直し方の案を書いてください。 |

| EN | If you find issues that are not in the policy (bugs, boundary conditions, error handling), put them in a separate section. |
|:---|:---|
| 読み | イフ ユー ファインド イシューズ ザッ(ト) アー ナッ(ト) イン ザ ポリスィ（バグズ、バウンダリー コンディションズ、エラー ハンドリン）、プッ(ト) ゼム イン ア セパレッ(ト) セクション |
| JP | 方針にない問題（バグ、境界条件、エラー処理）を見つけたら、別の節に分けてください。 |

| EN | If there is no problem, write "No issues". |
|:---|:---|
| 読み | イフ ゼア イズ ノウ プロブレム、ライ(ト) "ノウ イシューズ" |
| JP | 問題がなければ、「問題なし」と書いてください。 |

| EN | Do not invent findings. |
|:---|:---|
| 読み | ドゥー ノッ(ト) インヴェン(ト) ファインディングズ |
| JP | 指摘をでっち上げないでください。 |
